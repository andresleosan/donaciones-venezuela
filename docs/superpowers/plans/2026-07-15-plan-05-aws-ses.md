## Parte A — Manual (el plan la produce como `docs/guia-aws-ses.md`)

Guía en español, formato regla de oro (resumen inicial, un paso = una acción,
📍 dónde se hace, comando/click exacto, salida esperada, ⚠️ antes de lo
delicado):

1. 📍 **Consola AWS → SES, región `us-east-1`** → Verified identities →
   Create identity → **Email address** → poner el correo remitente (puede ser
   un Gmail) → Create. *Salida esperada:* estado «Verification pending» y un
   correo de AWS en esa bandeja; clic al enlace → estado «Verified».
2. 📍 **SES → Account dashboard → Request production access.** Mail type:
   Transactional; caso de uso: «One-time login codes for a humanitarian
   donations platform (Venezuela earthquake response); double opt-in by
   nature (user requests the code)». *Salida:* caso abierto; aprobación ~24 h.
   ⚠️ Mientras esté en **sandbox** solo se puede enviar A direcciones
   verificadas — suficiente para probar con tu propio correo.
3. 📍 **SES → SMTP settings → Create SMTP credentials** → anotar **SMTP user**
   y **SMTP password**. ⚠️ La password se muestra UNA sola vez; guárdala en tu
   gestor. (Son credenciales IAM restringidas a `ses:SendRawEmail` — mínimo
   privilegio, alineado con la postura security-first.)
4. 📍 **Supabase → proyecto `zryfwbjvlacorryzdaod` → Authentication → Emails →
   SMTP Settings** → Enable custom SMTP: host
   `email-smtp.us-east-1.amazonaws.com`, puerto `465`, usuario y password del
   paso 3, sender = el email verificado, sender name = «Donaciones Venezuela».
   Save. *Salida:* banner de guardado; el correo de prueba de Supabase llega.
5. 📍 **Supabase → Authentication → Rate Limits** → «Rate limit for sending
   emails»: subir de 2/h a **100/h** (con SMTP propio Supabase lo permite).
   Anotar el valor elegido en la guía (es parte de la defensa anti-bots).
6. 📍 **Supabase → Authentication → Emails → plantilla OTP/Magic Link**:
   asunto `Tu código / Your code: {{ .Token }}`; cuerpo bilingüe es primero,
   en después, texto plano, con `{{ .Token }}` bien visible y «si no pediste
   este código, ignora este correo».
7. **Verificación final:** pedir un código real desde `#acceso` en producción
   → llega en segundos, remitente nuevo, y en las cabeceras del correo se ve
   `via amazonses.com`. Si no llega: revisar Supabase → Logs → Auth.

## Parte B — Código (loopeable): anti-bots baratos

R5.1 prohíbe scripts externos → **no** Turnstile/reCAPTCHA (quedan anotados
como excepción posible que solo Luis puede aprobar). Defensa en tres capas:

1. **Honeypot** en el form de email de `#acceso` (`#acceso-email-form`):

```html
<input id="acceso-web" name="web" tabindex="-1" autocomplete="off"
       aria-hidden="true" class="hp-field" />
```

```css
.hp-field{position:absolute;left:-9999px;height:1px;width:1px;opacity:0}
```

   En el submit (`js/admin.js:1195`): si `$('#acceso-web').value` no está
   vacío → `return` silencioso mostrando el mismo mensaje de éxito genérico
   (no revelar el mecanismo). Los bots que rellenan todo caen aquí.
2. **Freno cliente**: tras un envío, `#acceso-enviar-btn` queda deshabilitado
   60 s con cuenta atrás en el propio botón — clave
   `access.waitResend` = «Reenviar en {s} s» / «Resend in {s}s»
   (`setInterval` que repinta el texto; al llegar a 0 restaura
   `access.sendCode`). Sobrevive al cambio de idioma (R1.3: el interval
   repinta con `t()` en cada tick).
3. **Freno servidor** (la defensa real): los rate limits del paso A5 — por
   email y por IP los aplica GoTrue. Documentado en la guía.

- i18n de todo texto nuevo en es+en (R1.2), versión `?v=`/`VERSION` (R5.4),
  commit Luismadef45 + push (R5.5).

   uno con 📍 y salida esperada, y ⚠️ en los pasos 2 y 3.
