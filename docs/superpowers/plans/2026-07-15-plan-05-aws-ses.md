# Plan 05 — AWS SES para los códigos de acceso (problema 5)

> **Para /build-loop:** solo la Parte B es loopeable. La Parte A son pasos
> manuales de Luis en la consola AWS/Supabase (guía estilo regla de oro).
> Decisión D2: **cuenta AWS sí, sin dominio** → verificar un email remitente.

**Meta:** que los códigos de 6 dígitos salgan por AWS SES (sin el límite de
~2-4 correos/hora del SMTP integrado de Supabase), lo más barato posible
(~$0.10 por 1.000 correos), con defensa anti-bots.

**Contexto clave:** los códigos **ya los envía Supabase Auth** (`/auth/v1/otp`,
ver plan 02). Aquí no se escribe un sistema de correos: se conecta SES como
**SMTP personalizado** de Supabase Auth y se endurecen los límites.

## Parte A — Manual (guía para Luis, generarla como entregable del plan)

El plan debe producir `docs/guia-aws-ses.md` en español con este contenido,
formato regla de oro (un paso = una acción, 📍 dónde, salida esperada, ⚠️):

1. **Consola AWS → SES** (región `us-east-1`): Verified identities → Create
   identity → Email address → verificar (llega correo de AWS).
2. **Pedir production access** (Account dashboard → Request production
   access; caso de uso: códigos OTP de app humanitaria; tarda ~24 h).
   Mientras esté en sandbox solo se puede enviar A direcciones verificadas.
3. **Crear credenciales SMTP** (SES → SMTP settings → Create SMTP
   credentials) → anotar usuario/clave SMTP (⚠️ se muestran una sola vez).
4. **Supabase → Authentication → Emails → SMTP Settings**: host
   `email-smtp.us-east-1.amazonaws.com`, puerto 465, user/clave del paso 3,
   sender = el email verificado. Guardar.
5. **Supabase → Authentication → Rate limits**: subir «emails per hour» a un
   valor razonable (p. ej. 100) — con SMTP propio Supabase lo permite.
6. **Plantilla del correo** (Authentication → Emails → Magic Link/OTP):
   asunto y cuerpo bilingüe es/en, remitente con nombre «Donaciones
   Venezuela». Incluir `{{ .Token }}`.
7. **Verificación final:** pedir un código desde `#acceso` en producción y
   confirmar que el correo llega con el remitente nuevo (mirar cabeceras:
   `via amazonses.com`).

## Parte B — Código (loopeable): anti-bots baratos

Sin scripts externos (R5.1 prohíbe CDN, así que **no** Turnstile/reCAPTCHA;
si Luis quisiera Turnstile sería una excepción explícita a R5.1 — dejarlo
anotado, no implementarlo):

1. **Honeypot**: campo `<input id="acceso-web" tabindex="-1" autocomplete="off"
   aria-hidden="true">` oculto por CSS en el form de `#acceso`; si viene lleno,
   no se llama a `/auth/v1/otp` (silencio, sin error).
2. **Freno cliente**: tras pedir un código, deshabilitar `#acceso-enviar-btn`
   60 s con cuenta atrás en el propio botón (`t('access.waitResend', {s})`).
3. **Freno servidor**: los rate limits de Supabase Auth del paso A5 son la
   defensa real (por IP y por email); documentar los valores elegidos en la
   guía.
4. i18n de todo texto nuevo (R1.2), versión `?v=`/`VERSION` (R5.4), commit
   Luismadef45 (R5.5).
