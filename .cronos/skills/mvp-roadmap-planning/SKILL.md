# MVP & Roadmap Planning

## Cuándo se activa
Después de priorizar el backlog (skill `product-strategy`), cuando hay que decidir qué entra en la primera versión desplegable y qué se pospone.

## Criterio para definir el MVP
Una feature entra al MVP solo si cumple las tres:
1. Es imprescindible para que el flujo principal funcione de punta a punta.
2. Su ausencia hace que el producto no sirva para su propósito central.
3. No tiene un sustituto manual aceptable a corto plazo (ej. "por ahora WhatsApp" no siempre es válido si el volumen es alto).

Todo lo demás va a v2 o v3.

## Estructura del roadmap
```
MVP (v1) - lanzamiento
  - [features imprescindibles]
v2 - primera iteración post-lanzamiento
  - [features importantes pero no bloqueantes]
v3 - visión a mediano plazo
  - [features de crecimiento/escala]
```

## Salida esperada
Sección "Roadmap" en `BRIEF.md` o `STACK.md` con esta estructura de 3 niveles, y una fecha estimada (no comprometida) solo para el MVP.
